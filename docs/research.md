# Windows 11 파일 탐색기와 macOS Finder 비교 조사

조사일: 2026-11-19. 대상 제품: Swift/AppKit 기반 macOS 26 파일 관리자.
목표: Windows 사용자의 탐색·선택·파일 조작 습관을 유지하는 것. 아래 ‘권고’와 우선순위는 조사에 근거한 제품 제안이다.
근거: Microsoft·Apple·각 앱 제작사의 공개 문서. 실기 비교는 하지 않았으며, Windows 빌드별 변화와 macOS 26에서의 실제 동작은 구현 시 재현 검증한다.
Apple 문서의 최신판에는 macOS 27 설명도 섞여 있어 신규 AI 기능은 범위에서 제외했다. ‘대표 불편’은 전환 과정의 마찰 후보이며 사용자 조사로 빈도를 측정한 결과는 아니다.

## 1. Windows 11 기능 기준

기본 기능·홈·탐색 창·보기·메뉴의 근거: [Microsoft File Explorer 안내](https://support.microsoft.com/en-us/windows/experience/fileexplorer/file-explorer-in-windows).
주소창·검색창·세부 정보·Gallery의 근거: [Microsoft 2023 기능 업데이트](https://support.microsoft.com/en-gb/servicing/os/configuration-updates/2023/08/september-26-2023-windows-configuration-update). 최신 배치는 빌드에 따라 달라질 수 있다.

| 영역 | Windows 기준 동작 | macOS 제품에 적용할 권고 |
| --- | --- | --- |
| 홈/빠른 액세스 | 고정 폴더·최근/즐겨찾기 항목 | 홈과 고정 목록 제공, 최근 항목 표시 선택 |

| 기타 보기 | 타일·콘텐츠, 간격 조절 | P2; 기본 모드와 선택 동작 통일 |

| 속성 창 | 선택 항목 속성 확인 | 파일/폴더 정보, 합산 크기, 위치, 권한·잠금 상태 |
| 파일 작업 | 복사·이동·삭제·이름 변경·새 폴더 | 진행률·취소·충돌 처리·지원 작업의 실행 취소 |
| 표시 설정 | 숨김 항목·확장자·선택 체크박스 | 숨김/확장자를 메뉴에서 즉시 전환 |

목록/자세히/아이콘/타일의 구조적 차이는 [Microsoft List-View 설명](https://learn.microsoft.com/en-us/windows/win32/controls/list-view-controls-overview)에 근거한다. 상태 표시줄·열 조작의 세부 배치와 기본 정렬은 지식 기반 정리이며 기준 Windows 빌드에서 확인할 항목이다.

| 항목 | 정확성 및 적용 메모 |
| --- | --- |
| Backspace | 공식 탐색기 표는 ‘이전 폴더’다. 상위 이동은 Alt+↑. 열기/저장 대화상자의 Backspace 설명과 혼동하지 않는다. |
| Enter·선택·Esc·Page 키 | 일반 목록 조작을 포함한 지식 기반 보충이다. 포커스/편집 상태별 재현 검증 필요. |

| 타이핑 점프 | 입력 누적·시간 초과 초기화는 [Microsoft 증분 검색 설명](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/nf-commctrl-listview_getisearchstring)에 근거. 검색 상자와 별개다. |

| 편집 중 | Enter는 확정, Backspace/Delete는 문자 삭제, Esc는 편집 취소. 파일 명령보다 텍스트 편집이 우선한다. |

## 3. Finder에서 생기는 전환 마찰

Finder의 기본 키와 이동 붙여넣기는 [Apple 단축키](https://support.apple.com/en-us/102650), Return 이름 변경은 [Apple Windows 전환 안내](https://support.apple.com/en-kz/102323)에 근거한다. 기능의 부재와 발견하기 어려운 기능을 구분했다.

| 불편 인식 | Finder의 실제 상태/대응 | 제품 권고 |
| --- | --- | --- |
| ‘잘라내기/붙여넣기가 없다’ | 파일용 Cmd+X 대신 Cmd+C → Option+Cmd+V로 이동 가능 | 잘라내기 메뉴·Ctrl/Cmd+X와 흐린 선택 표시 |
| Enter로 열리지 않는다 | Return은 이름 변경; Cmd+O 또는 Cmd+↓로 열기 | Enter 열기, F2 이름 변경 |
| Backspace로 올라가지 않는다 | 부모는 Cmd+↑; 이전/다음은 Cmd+[ / ] | Backspace 이전, 별도 위로 버튼 |
| 상위 폴더 버튼이 안 보인다 | 이동 메뉴·Cmd+↑·제목 Cmd+클릭 등으로 이동 가능 | 위로 버튼과 경로 계층을 상시 노출 |
| 경로 입력이 어렵다 | Cmd+Shift+G ‘폴더로 이동’ 지원; 편집형 상시 주소창과 다름 | 주소창 직접 입력·붙여넣기·완성 |
| 숨김 파일이 안 보인다 | Cmd+Shift+. 토글이 알려진 방법; 메뉴 발견성이 낮음 | ‘숨김 항목 표시’와 현재 상태 노출 |
| ‘폴더 우선 정렬이 없다’ | 설정 → 고급 → 이름 정렬 시 폴더 위에 유지 가능 | 기본 켬; 모든 열 정렬에서도 적용 여부 선택 |
| 새 텍스트 파일을 못 만든다 | 일반적인 기본 Finder 메뉴는 새 폴더 중심; 파일 생성은 앱에서 수행 | 빈 공간 메뉴의 새 파일/텍스트 파일 |
| 경로 복사가 어렵다 | Option+우클릭 → 경로 이름 복사, 경로 막대 메뉴도 사용 가능 | 상시 ‘경로 복사’; POSIX 경로 기본 |
| 폴더 크기가 빈칸이다 | 목록 보기 옵션의 ‘모든 크기 계산’으로 가능 | 요청 시 비동기 합산, 계산 중/부분 실패 구분 |
| Delete가 삭제하지 않는다 | Cmd+Delete로 휴지통 이동 | Mac 키보드의 Backspace와 Forward Delete 구분 |
| 검색이 너무 넓다 | 설정에서 전체 Mac/현재 폴더/이전 검색 범위 선택 가능 | 현재 폴더 기본, 하위 포함 여부 표시 |
| 확장자가 안 보인다 | 고급 설정에서 모든 확장자 표시 가능 | 확장자 표시 기본 켬, 이름 변경 시 기본 이름만 선택 |
| 드래그 결과가 헷갈린다 | 볼륨·Option/Cmd 수식키에 따라 복사/이동 차이 | 커서 배지와 대상·예상 동작 명시 |
| 탭·미리 보기가 없다고 느낀다 | Finder에도 탭·미리 보기·Space Quick Look 존재 | Windows식 배치와 키를 제공; 신규 기능으로 오인하지 않기 |

폴더 우선·검색 범위·확장자 설정: [Apple Finder 설정(macOS 26)](https://support.apple.com/en-gb/guide/mac-help/mchlp2803/26/mac/26).
경로 입력: [Apple 폴더로 이동](https://support.apple.com/en-mt/guide/mac-help/mchlp1236/27/mac/27). 경로 복사: [Apple 경로 설명](https://support.apple.com/en-asia/guide/terminal/apd3cf6fe02-3ec8-48f1-951f-866e52955fc8/mac).
숨김 토글·모든 크기 계산·기본 새 파일 메뉴 부재는 지식 기반 항목이며 macOS 26 실기 확인이 남아 있다. Apple 26 개별 안내 일부는 조회 제한으로 본문을 가져오지 못해 검색 색인과 공통 문서를 함께 사용했다.

## 6. Ctrl/Cmd 및 macOS 입력 권고

권고: 기본은 ‘Windows 동작 + Ctrl/Cmd 동시 지원’. 문자 명령 일부에 별칭을 주되 Ctrl를 일괄 Cmd로 바꾸지 않는다. 파일 영역에서 적용하고 입력창은 AppKit 표준 편집을 우선한다.

| 상황 | 권고 매핑/정책 | 이유 |
| --- | --- | --- |
| 복사/잘라내기/붙여넣기 | Ctrl/Cmd+C·X·V 모두; Option+Cmd+V 이동도 제공 | 전환 사용자와 기존 Mac 습관 수용 |
| 전체 선택·Undo | Ctrl/Cmd+A·Z, Ctrl+Y/Cmd+Shift+Z 다시 실행 | 메뉴에는 Mac 기본 키 표시, 도움말에 두 계열 기재 |
| 주소·검색·새 폴더·탭 | Ctrl/Cmd+L·F·Shift+N·T·W; Ctrl+Tab 계열 | 직접 대응이 명확한 명령부터 지원 |
| 열기·이름 변경·이력 | Enter 열기·F2 이름 변경; Backspace 이전; Option+↑ 부모, Option+←/→ 이력 | Windows Alt는 Mac Option에 대응; Cmd+O/↓·Cmd+↑·Cmd+[ / ] 별칭 유지 |
| Mac Delete 키 | ⌫(Backspace)는 이전; Fn+⌫/⌦(Forward Delete)는 휴지통; Cmd+⌫도 휴지통 | Mac의 ‘delete’ 표기는 Windows Delete와 물리 동작이 다름 |
| 영구 삭제 | Shift+⌦, 즉 Shift+Fn+⌫; 메뉴 명령과 확인 제공 | Shift+⌫와 혼동하여 삭제하지 않도록 구별 |
| Ctrl+D와 Cmd+D | Ctrl+D 휴지통, Cmd+D 복제 | 같은 문자여도 Windows와 Finder 의미가 충돌 |
| Ctrl+E와 Cmd+E | Ctrl+E 검색, Cmd+E 볼륨 추출 | Cmd+E의 Finder 의미 보존; 무조건 별칭 금지 |
| 복수 선택 마우스 | Cmd+클릭·Shift+클릭 기본; Control+클릭은 컨텍스트 메뉴 유지 | Windows식 Ctrl+클릭과 macOS 보조 클릭이 충돌 |
| 텍스트/한글 조합 중 | Ctrl+A/E·방향키·Delete·Enter는 편집/조합 처리 우선 | 주소 편집 중 전체 파일 선택·삭제·이동 방지 |
| F2/F5/F4·숫자패드 | Fn 필요 가능성 안내; 모든 동작을 메뉴/버튼으로도 제공 | Mac 기능키·키보드 배열 차이 |
| OS가 선점한 키 | Cmd+Tab·Spotlight·Mission Control 등 전역 키를 가로채지 않음 | 앱 내부 호환 범위를 명확히 유지 |

Mac 기본 키의 근거는 [Apple 단축키 안내](https://support.apple.com/en-us/102650). 위 병행 지원·충돌 해소 방식은 제품 설계 권고이며 기존 Finder 동작을 그대로 설명한 표가 아니다.

## 7. 구현 전 확정·검증할 항목

| 항목 | 남은 확인 |
| --- | --- |
| 기준 환경 | Windows 11의 정확한 버전/빌드와 macOS 26.x를 기록한 뒤 같은 파일 세트로 비교 |
| 키보드/입력기 | Mac 내장/Windows 외장 키보드, F키 설정, 한·영 전환·조합·텍스트 포커스별 회귀 확인 |
| 경로 의미 | POSIX·~/·마운트 볼륨 우선; C:\\·UNC는 실제 대응이 있을 때만 변환하고 미지원 입력 안내 |
| 정렬/파일 이름 | 자연수 정렬(file2/file10), 한글·대소문자·확장자·숨김·패키지·별칭·심볼릭 링크 검증 |
| 파일 작업 | 같은/다른 볼륨·권한 거부·파일 소멸·충돌·중단·휴지통 불가에서 원본/결과 확인 |
| 성능/연동 | 큰 폴더·썸네일·폴더 합산은 비동기; Finder/타 앱 클립보드와의 이동 의미는 별도 실기 검증 |
| 배포 접근 권한 | App Sandbox 배포 여부와 접근 범위 설계를 정하고, 접근 불가 상태를 명시; OS 보호 우회 전제 금지 |

‘Windows와 똑같음’의 판정은 P0 시나리오별 결과·선택·이력·키 동작으로 한다. 드라이브 문자·NTFS ACL·Windows 셸 확장 등 OS 고유 의미는 macOS에 맞게 대응하고 차이를 도움말에 명시한다.
